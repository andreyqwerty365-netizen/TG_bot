## Найденное в ядре

`CRMService.ingest` сохраняет источник до внешнего разбора, уникальный ключ включает владельца/канал/account/external_id и отдельную revision. `process` имеет минутное владение разбором и кэширует успешно применённый результат. Изменения задачи, история и задания записываются одной транзакцией под блокировкой владельца. Подтверждение проверяет версию предложения и ожидаемую версию задачи. Раньше любая интерпретация с reminder порождала предложение; разговорного состояния и очереди коротких ответов не было.

Worker уже сохраняет intent перед отправкой, использует SKIP LOCKED и fencing token, lease 30 секунд, ограниченные повторы известных ошибок; неопределённая доставка становится unknown и не повторяется автоматически. Exact освобождён от лимита инициатив, repeat его расходует. Сводки, ротация и расписание не зависят от интерпретатора. FastAPI задаёт владельца server-side и проверяет отдельные credentials владельца/почтового тестового connector.

## Изменения схемы и полномочий

Аддитивная миграция `24b831882dea` добавляет source metadata, только текстовые draft_steps, per-account Conversation (последняя задача/напоминание/источник), Dialogue с proposal_version/task expected_version и 24-часовым истечением, TelegramReceipt, OutgoingReply, reply-kind Job, AIBudget/AIReservation. Старые миграции не редактируются. Старые записи остаются, draft_steps получают пустой список. Downgrade допустим только в disposable стенде без reply jobs; при наличии таких заданий он отказывает вместо скрытого удаления доставки. Для настоящих данных нужен проверенный backup/restore, здесь он не выполнялся.

Только серверная детерминированная грамматика даёт полномочия немедленной команды владельца. Ответ SDK не содержит command/answer, authority или owner_id. Предложения показывают действие/целевой заголовок/точное предлагаемое значение перед подтверждением. «Да» связывается с конкретным source/proposal_version, дата — с сохранённым pending_action/task version. Несвязанная фраза не разрешает старый вопрос; явный reply может адресовать его до истечения срока. В сокращённом контексте нельзя доказывать уникальность по отсутствующим задачам. При редактировании пересылки доверие не повышается.

## Официальный SDK и ограничения проверки

Зафиксирован официальный `openai==3.31.0` из PyPI (project repository openai/openai-python), с `httpx2==2.13.1`; остальные версии в requirements.lock. Проверены сигнатура установленного `client.responses.parse`, фактический strict JSON Schema и wire payload настоящего SDK через MockTransport. Прочитаны официальные README и helpers.md: https://github.com/openai/openai-python/blob/main/README.md и https://github.com/openai/openai-python/blob/main/helpers.md (раздел Parsing Responses API output). Они описывают Responses как основной API и `responses.parse(..., text_format=PydanticModel)`/`output_parsed`, refusal и неполный результат.

Модель/тариф не выбраны. Store=false, truncation=disabled, retries=0. Передаются только текущий источник, проверенный канал/даты/пояс, до 8 кандидатов с ID/version/кратким заголовком и до 8 ID вопросов. Нет owner/user/chat ID, всего inbox, секретов или журналов. Без каждого из флага, ключа, разрешённой модели, категорий согласия, положительного бюджета и действующей таблицы цен клиент SDK вообще не создаётся. Перед запросом резервируется полная доверенная model input_token_ceiling плюс max_output по явным ценам, а сериализованный ввод проверяется консервативной границей в байтах с запасом схемы/протокола. Это сознательно может блокировать запрос раньше фактического лимита.

Бюджет хранится в micro-USD под PostgreSQL row lock по владельцу/UTC-месяцу. Предварительная резервация учитывает конкуренцию; usage сверяет расходы. Неизвестный исход/usage списывает верхнюю границу, автоматический повтор этого source запрещён. Crash до сверки оставляет reserved, требуя отдельной проверки счетов, без автоматического освобождения. Лимит можно уменьшить конфигурацией; повышение уже созданного месяца требует отдельного администрирования, API увеличения не предоставлен. 80% учитывает spent+reserved, предупреждение сохраняется и доступно через /ai/status и queued reply; 100% блокирует расход, а не только показывает уведомление. Предел входа 8000 символов, выхода 512 tokens по умолчанию; HTTP тело 256 KiB, тайм-аут фазы ≤15 секунд и ограничение чтения 20 секунд. SDK не наследует произвольные OPENAI_BASE_URL/organization/project из среды.

## Telegram

Защищённый /adapters/synthetic-telegram использует синтетические Updates и owner credential. /telegram/webhook выключен по умолчанию, требует constant-time secret и allowlists фактического from.id/chat.id плюс server bot_id; группы отдельно выключены. Payload owner_id не используется. Update receipt и source коммитятся вместе, технический повтор не дублирует reply; если процесс упал между commit источника и разбором, replay возобновляет pending/просроченный processing. Ошибочные разборы доступны для явного retry, повторы Update не создают цикл повторных внешних запросов.

Forward_origin/legacy forward_date, edit revision, caption и reply binding сохраняются; голос/медиа без текста получают честное уточнение. Caption читается как текст, файл не анализируется. Reply к записанному bot message разрешается по успешному Attempt.provider_id и тому же owner/account. Новый message_id того же текста — новый источник. Нет polling и вызова setWebhook.

Исходящий адаптер отдельно выключен, требует CRM_TELEGRAM_TEST_TOKEN, server bot ID и разрешённый chat; getMe сверяет отдельного бота. Рабочий BOT_TOKEN никогда не читается. Только plain text, без parse_mode, отключён preview. getMe/sendMessage имеют 3-секундные тайм-ауты фаз, 5-секундную проверку чтения и 64 KiB тела, суммарно короче default lease. API ok=false — известная ошибка, отсутствие достоверного результата — unknown; автоматический resend после unknown запрещён. Реального getMe/sendMessage не выполняли.

Календарные значения SDK сверяются независимо: одна явная ISO-дата, относительное слово/день недели владельца по получению и поясу, точные HH:MM для instant, проверка DST и совпадения нормализованной даты/часов. Неподдерживаемое выражение требует переформулировать дату, валидный JSON не разрешает выдуманный момент. Новые planned_on/return_on/focus из интерпретации требуют предложения и применяются только после подтверждения; draft_steps остаются текстом.

## Честные ограничения

Грамматика ограничена очевидными фразами и датами; произвольный русский при выключенной модели остаётся сохранённым с ошибкой разбора/уточнением. 144 размеченных примера (36 held_out) подготовлены для будущей оценки; это не метрики GPT. Не выполнены live NLP, live Telegram, production receiver switch, production migration, encrypted backup/restore, реальная почта, нагрузочный p95 и пилот. Будущая интеграция с текущим ботом должна использовать одного update consumer и согласованный sender, отдельного второго polling/webhook здесь нет.
