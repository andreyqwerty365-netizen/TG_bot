# Регулярные дела, небольшие шаги и подтверждаемые предложения

Веб работает с той же PostgreSQL, что и Telegram. Реальные интеграции остаются выключенными. Настройка повторений и подтверждение плана доступны в карточке дела; предложения раннего плана и старта — в «Сегодня».

## Повторение

Создайте дело, откройте карточку и «Настроить повторение». Явно задайте день этого экземпляра, период в днях/неделях/месяцах и интервал. Точное уведомление необязательно: его нужно отдельно включить и выбрать время. Пояс берётся из явно настроенного профиля и сохраняется в правиле. Без пояса новое правило отклоняется. Предпочтительное время может быть показано в форме, но само по себе не включает уведомление.

Один ряд содержит правило и отдельные экземпляры. Выполнение или отмена экземпляра сохраняет правило и одной транзакцией создаёт следующий будущий экземпляр с собственным источником, историей и, если выбрано, уведомлением. Уникальные ограничения PostgreSQL запрещают два открытых экземпляра и повтор одной даты. Ошибка сохранения следующего экземпляра откатывает выполнение текущего. Следующий день считается от календарной опорной даты, а не от количества часов с момента выполнения.

При ежемесячном повторении 31 января переходит в последний день февраля, затем снова в 31 марта. После простоя не создаётся весь накопившийся ряд: старое незавершённое дело остаётся открытым, а после решения владельца появляется ближайший будущий период. Молчание не закрывает экземпляр. Будущий экземпляр виден в полном списке, а в ежедневном обзоре появляется в свой день. Повторное общее «выполнил» не выбирает будущий экземпляр; явное действие в его веб-карточке допустимо.

Дедлайн текущего экземпляра остаётся его внешним сроком и не копируется дальше. Проект, заголовок и исходный черновик шагов входят в шаблон будущих экземпляров. Редактирование обычной карточки меняет только этот экземпляр. «Правило повторения» позволяет отдельно изменить период, время и название для следующих экземпляров, сохраняя текущие данные. Пояс действующего правила сохраняется при смене пояса профиля. «Остановить повторение» останавливает ряд и оставляет текущий экземпляр. Если открытого экземпляра уже нет, возобновление старого ряда отклоняется: нужно создать новое дело и правило.

Если выбранное местное время отсутствует или неоднозначно при переводе часов, экземпляр сохраняется с предупреждением, а точное уведомление не угадывается. В карточке можно выбрать другой момент. Прошедшее на момент первоначальной настройки время также не создаёт отправку задним числом. Настоящая доставка работает по прежним правилам очереди; в тестах она только синтетическая.

## Шаги

В карточке можно сохранить до 12 различных непустых шагов длиной до 500 символов. Это черновой текст, пока владелец не нажал «Создать N задачи из плана». Одно подтверждение текущей версии создаёт весь набор. Дочерние дела связаны с родителем, наследуют проект и получают собственные источники/историю. Их дедлайны, дни выполнения и уведомления не выдумываются. Родитель не закрывается при создании или выполнении дочерних дел.

Повтор запроса с тем же request_id возвращает прежний результат. Подтверждение старой версии после правки отклоняется. Уже подтверждённый вариант не создаёт второй набор. Новая редакция черновика требует отдельного подтверждения и может создать новый набор; старые задачи сохраняются. Из карточки доступны переходы к дочерним делам и обратно.

Модель может предложить новую редакцию существующего черновика операцией `propose_update/change=steps`. Действующий план сохраняется до подтверждения владельца; принятие такого предложения меняет только черновик, а создание дочерних задач требует отдельного подтверждения всего набора. Реальный ИИ не включался, качество автоматического разбиения не оценивалось.

## Ранний план и небольшой старт

Source worker раз в пять минут подготавливает локальные предложения; кнопка «Подготовить предложения» делает это по запросу. Генерация сохраняет только предложения, не меняет задачи и не создаёт уведомлений. «Принять план» назначает более ранний день выполнения и сохраняет внешний дедлайн. «Начать с шага» переводит подтверждённое дело в работу, не создавая подзадач. При наличии черновика используется его первый шаг; иначе показывается явно общий приём для старта, без заявления о понимании конкретной задачи.

По умолчанию ранний план предлагается для срока в ближайшие 7 суток с опережением на 2 дня, не раньше текущего дня. Уже заданный план не заменяется автоматически. Видимыми остаются предложения актуальной версии активного дела. Редактирование, завершение, истёкшая дата или смена версии запрещают старое подтверждение. Скрытый или принятый вариант не предлагается снова без содержательного изменения срока/плана шагов. В сводку входит количество актуальных предложений; отдельная инициатива не добавляется, лимиты доставки не повышаются.

## Ограниченная адаптация

Когда владелец явно выбрал одинаковое время уведомления минимум для трёх разных дел за последние 14 дней, система может предложить это время для будущих форм. Изменение названия или проекта с сохранённым уведомлением не считается выбором времени. Принятие проверяет версию профиля и сохраняет только предпочтение; все существующие уведомления остаются на своих моментах. Пауза ИИ и лимит инициатив не меняются. Вручную заданное предпочтение имеет приоритет, другое автоматически не предлагается. Скрытие предложения не является согласием.

Серверные границы заданы в `PlanningPolicy`, а не в промпте модели. Переменные из `.env.example`: `CRM_PLANNING_EARLY_HORIZON_DAYS=7`, `CRM_PLANNING_EARLY_LEAD_DAYS=2`, `CRM_PLANNING_HISTORY_DAYS=14`, `CRM_PLANNING_REQUIRED_CHOICES=3`, `CRM_PLANNING_TASK_LIMIT=100`. Обрабатывается ограниченный набор активных дел, сначала явный фокус, затем старые. Неверные диапазоны конфигурации отклоняются. Период и опорный день каждого регулярного дела задаются владельцем отдельно.

## Проверка и запуск

Новые аддитивные миграции — `a8273f1d804c` и `b9184f723ade`. Применять их только к разрешённой среде; рабочая миграция в этой итерации не выполнялась. Обычный запуск из `personal-crm/` с настроенной отдельной БД и владельцем:

    python -m alembic upgrade head
    python -m uvicorn personal_crm.api:create_app --factory --host 127.0.0.1 --port 8001
    python -m personal_crm.source_worker

После `npm ci`, `npm test`, `npm run build` в `web/` открыть `/app/`. Основной API не подменяет почту примерами. Для полного E2E использовать только охраняемую синтетическую фабрику и отдельную `personal_crm_test_web` по [MAIL.md](MAIL.md). Из `web/` выполнить `npm run test:e2e`. Новые `planning.spec.ts` проверяют повторение, отдельную остановку ряда, черновик, подтверждение набора и переходы к детям на desktop/mobile.

Backend проверяется на настоящей disposable PostgreSQL с `CRM_TEST_DATABASE_URL`, имя БД `personal_crm_test*`; pytest очищает только эту специально разрешённую БД:

    .venv\Scripts\python.exe -m pytest -q

`test_continuation_d.py` проверяет календарь/простой/DST, конкуренцию и rollback, подтверждение и replay шагов, версии/владельца, ранний план и предпочтения. Точная приёмка записана в [ACCEPTANCE.md](ACCEPTANCE.md). Свободный разговорный ввод произвольного правила повторения пока не реализован: правило задаётся вебом/HTTP. Live провайдеры, backup/restore, импорт старой базы и production-пилот остаются отдельными объёмами.
