# OpenAI API: обязательные границы интеграции

Дата: 13 октября 2026 года. Перенос дополнения CRM_OpenAI_API_addendum_v0.2.md. Статус: требования, не включённая платная интеграция. Основной документ `REQUIREMENTS.md` не заменяется.

## Назначение

R19: разрешено предусмотреть GPT через OpenAI API. Это не выбор конкретной модели, бюджета или разрешение передавать весь ящик. Хранение задач, поиск и уже назначенные напоминания не должны зависеть от модели.

Модель применяется для извлечения действий, исполнителей, сроков, неоднозначностей из текущей фразы/пересылки; подготовки предложений из разрешённой почты; интерпретации разговорных команд с ограниченным контекстом; чернового разбиения сложных задач; необязательного улучшения формулировок сводок. Не вызывать модель для проверки часов или на каждом цикле фонового процесса.

## Интерфейс

Стартовый выбор: официальный OpenAI SDK и Responses API. Использовать Structured Outputs с поддерживаемой JSON Schema. Модель конфигурируемая, без жёстко зашитого идентификатора в бизнес-логике. При реализации проверить совместимость по актуальной официальной документации. Выбрать модель позже по размеченному проверочному корпусу, задержке и стоимости.

Результат содержит предлагаемую операцию, тип записи, идентификатор источника, исходные формулировки дат, значения и точность, исполнителя, неоднозначности, необходимость уточнения, предполагаемую связь с существующим делом и его версией. Формально правильный JSON не доказывает правильность смысла: сервер независимо проверяет даты, владельца, допустимость перехода состояния, контекст подтверждения и границы доверия. Отказ модели, неполный результат, ошибка сети и ошибка валидации являются отдельными состояниями.

Порядок: сохранить источник в БД; при необходимости получить интерпретацию; проверить схему и смысл; проверить полномочия; сохранить задачу/предложение/уточнение; только после commit сообщить результат. Модель не имеет прямого произвольного доступа на изменение БД, чтение всего ящика и отправку сообщений.

Очевидная новая задача из пересылки может создаваться автоматически. Почта всегда формирует только предложение. Изменение существующего дела по инициативе ИИ требует подтверждения. Явная однозначная команда владельца уже является подтверждением.

## Секреты и данные

OPENAI_API_KEY находится только на сервере: переменная окружения или хранилище секретов. Не в браузере, сообщениях, репозитории, образе контейнера, тестовых fixtures или логах. Примеры содержат пустые placeholders. Предусмотреть замену ключа. Не использовать найденные ключи действующего проекта.

Передавать текущий текст и минимально необходимый контекст, не весь ящик и историю дел. Пересылки и письма являются недоверенными данными, не инструкциями. До явного разрешения категорий передачи реальные внешние обращения выключены. Для Responses предусмотреть store=false, если режим совместим. Это не гарантия полного отсутствия хранения у провайдера: актуальные условия журналов проверяются отдельно. Использование данных API для обучения по умолчанию выключено без согласия, но это не тождественно нулевому хранению.

## Расходы и сбои

API оплачивается отдельно от подписки ChatGPT. Разрешение разработать модуль не разрешает автоматически использовать платные ресурсы. Реальные вызовы включать только после настройки ключа, ненулевого бюджета и разрешения передачи. По умолчанию fake-адаптер, внешние вызовы выключены.

Нужны учёт использования; лимит размеров входа/выхода; ограниченные повторы; тайм-ауты; месячный лимит; предупреждение на 80%; остановка новых платных обращений на 100%. Перед вызовом проверять и резервировать максимально допустимые расходы, учитывая уже начатые и параллельные запросы. Не выдавать только предупреждение за работающую блокировку. Источник цен/валюта/модель должны быть заданы явно, без выдуманного тарифа. При недоступной достоверной оценке затрат не обходить бюджет молча.

Не вызывать повторно модель при техническом дубле уже обработанного источника. Результат можно переиспользовать для неизменившейся версии источника, но не для произвольно похожих разных обязательств.

При отсутствии/отзыве ключа, недоступности API, отказе модели или исчерпании бюджета продолжают работать существующие задачи, хранение, поиск, явные простые команды и доставка назначенных напоминаний. Новое свободное сообщение сохраняется для разбора позже. Не заявлять эквивалентное понимание произвольного русского текста без модели; неоднозначные даты не активируют выдуманное расписание.

## Приёмка

O-T01: нет ключа, сохранённые задачи и напоминания доступны.
O-T02: неверный/отозванный ключ не раскрывается в ошибке, источник не теряется.
O-T03: тайм-аут, ошибка, отказ, неполный результат не дают ложного подтверждения создания/изменения.
O-T04: валидный JSON с неверной датой или запрещённым действием не применяется автоматически.
O-T05: инструкция изменить чужие задачи внутри письма не расширяет полномочия.
O-T06: при лимите новые обращения блокируются, существующие напоминания продолжаются.
O-T07: ключ отсутствует в исходниках, клиентской сборке и диагностике.
O-T08: технический повтор источника не вызывает повторного платного разбора и операции без необходимости.

Эти проверки являются целями, а не заявлением об их прохождении. Проверки состояния и политики выполняются с fake-транспортом. Реальное качество модели измеряется отдельно на независимой части размеченного корпуса; fake-ответы не доказывают качество GPT.
