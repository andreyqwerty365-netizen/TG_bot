# Ежедневные внешние копии старого бота

## Purpose and context

Владелец 2026-10-15 поручил настроить ежедневные зашифрованные копии обеих SQLite старого бота в уже оплаченное S3 и проверить восстановление. Работа ограничена personal-crm; рабочий процесс Telegram не перезапускается. Код personal_crm.legacy_backup использует SQLite online backup API и существующие AES-GCM/S3 адаптеры. Секреты и данные находятся только в приватных каталогах оператора.

## Milestones and validation

Первый этап: из personal-crm запустить `.venv/Scripts/python.exe -m pytest tests/test_legacy_backup.py`. Сначала импорт отсутствует, после реализации тесты должны пройти. Архив содержит только notes.db и workouts.sqlite3; восстановление допускается только в новый каталог, проверяет аутентичность, контрольные суммы, integrity_check, схему и прикладные строки. WAL проверяется открытым соединением с ещё не checkpoint-нутой записью.

Второй этап: отдельный Docker job читает рабочие базы через read-only mount; host wrapper держит mode=ro/query_only соединения для наличия WAL/SHM. Job использует tmpfs для открытых снимков и отдельный приватный ключ. Daily systemd timer запускает job в 03:20 Europe/Moscow, пропущенный запуск выполняется после включения сервера. Повторные запуски безопасны: уникальные имена и блокировка; crash-lock разбирает оператор. После upload требуется readback и проверка; только затем обновляется latest и удаляются собственные валидные архивы старше 30 дней.

Третий этап: на VPS загрузить архив обратно из S3, восстановить обе базы в новый root-private каталог и сравнить fingerprint с зашифрованным manifest. Проверить timer, exit code и здоровый единственный bot/CRM. Ключ копируется в ранее согласованный приватный каталог Windows вне Git. Изменения публикуются в текущую ветку без merge и без root bot changes.

## Decision Log

2026-10-15: отдельный bucket и отдельный ключ для legacy SQLite; действующие CRM backups PostgreSQL сохраняют свои ключ/формат/расписание. Оба SQLite снимаются последовательно через backup API; межбазовой транзакции нет, что соответствует существующему приложению с независимыми базами. Бот token/env и логи не входят в архив данных. Их операторская конфигурация восстанавливается отдельно.

## Surprises & Discoveries

На рабочем trainer есть WAL/SHM, поэтому простое копирование файлов и immutable read живого источника неприемлемы. Реальный read-only mount должен быть проверен отдельно. Размер обеих баз сейчас меньше 1 MiB; формат ограничивает каждую базу 20 MiB и полный ciphertext 64 MiB, превышение завершает job ошибкой.
