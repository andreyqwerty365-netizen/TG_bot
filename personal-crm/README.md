# Personal CRM

Изолированная разработка личной системы дел внутри существующего репозитория Telegram-бота. Рабочая ветка передачи: `codex/personal-crm-bootstrap`. Ветка `master` и текущий бот не изменяются.

## Материалы

- `AGENTS.md`: границы изменений и обязательные правила разработки.
- `CODEX_TASK.md`: исполняемое первое задание для Codex, включая создание исходников и запуск тестов.
- `docs/REQUIREMENTS.md`: 19 пользовательских требований, 17 изменяемых проектных решений, поведение и архитектура.
- `docs/OPENAI_API.md`: необязательный GPT-модуль, секреты, бюджет, полномочия и обработка сбоев.
- `docs/ACCEPTANCE.md`: 28 основных и 8 API-проверок, требования к качеству модели и эксплуатации.

## Состояние на момент передачи

Подготовлены требования и задание. Код Personal CRM ещё не реализован, тесты нового модуля не запускались. Создание этих файлов само по себе не доказывает запуск облачного агента. Фактический статус запуска проверяется по ответу интеграции Codex в PR или по облачной задаче.

Первый результат разработки: надёжное сохранение источника, задача/предложение, история, постоянная очередь напоминаний и воспроизводимые тесты на PostgreSQL с fake-адаптерами. Не очередной план вместо реализации.

## Запуск задания вручную при необходимости

В Codex выбрать этот репозиторий и ветку `codex/personal-crm-bootstrap`, затем отправить:

> Прочитай `personal-crm/AGENTS.md`, `personal-crm/CODEX_TASK.md` и все три документа в `personal-crm/docs/`. Выполни `CODEX_TASK.md`: создай структуру приложения внутри `personal-crm/` и реализуй первый проверяемый сквозной сценарий с PostgreSQL, тестами и fake-интеграциями. Не останавливайся на плане. Действующий бот и master не менять, реальные ключи и данные не использовать. Сохрани изменения в отдельной ветке/PR и отчитайся по фактически выполненным проверкам.

Не запускать одно и то же задание повторно, если облачная задача уже выполняется.

## Безопасность

Репозиторий публичный. Здесь нет настоящих API-ключей, сообщений, писем и дампов. Реальные интеграции по умолчанию отключены. Не выполнять production-миграцию, переключение Telegram или развёртывание без отдельного разрешения.

Команды установки, миграций, тестов и демонстрации должен добавить реализующий агент по фактическому коду. Не подменять этот раздел несуществующими командами запуска.
