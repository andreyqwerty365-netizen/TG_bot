## Surprises & Discoveries

Предыдущий аудит описывает 124 успешных теста, но не содержит тестов перечисленных пользователем отрицаний и короткого ответа времени. `language.py` стирает вопросительные знаки до распознавания завершения. `context.py` читает только 65 последних задач и запрещает поиск по названию при более восьми кандидатах. Редактирование источника всегда превращается в изменение заголовка. `BudgetLedger.reserve` блокирует даже статус failed с нулевым списанием. Worker восстанавливает доставку, но не подбирает необработанные источники без повторного Telegram Update.

На Windows отсутствовали полноценный Git и PostgreSQL. Официальный переносимый Git находится вне репозитория в `../.tools/mingit`; PostgreSQL для тестов также загружается вне репозитория. Graphify не запустился: установленный Python launcher недоступен, попытка использовать его пакеты из Python 3.12 обнаружила несовместимый бинарный tree_sitter. Исходники анализируются напрямую; граф не объявляется построенным.

## Decision Log

Опасное завершение блокировать детерминированно до обращения к модели. Подтверждения проверять по владельцу, аккаунту и версии. Ограниченный контекст модели не использовать как доказательство уникальности задачи: однозначные ссылки и поиск должны проверяться запросом ко всей PostgreSQL.

Для краткого ответа времени сохранять уже разрешённую календарную дату в pending_action, чтобы перезапуск или смена дня не переинтерпретировали «завтра». Потенциально оплаченные запросы не повторять автоматически. Статус достоверно неоплаченного отказа допускает новый резерв, только после проверки бюджета; повтор источника Telegram не запускает бесконечный цикл.

## Context and Orientation

`src/personal_crm/service.py` сохраняет SourceVersion до интерпретации, затем применяет изменения и историю под блокировкой профиля. `language.py` распознаёт ограниченные команды. `context.py` строит кандидатов и постоянные вопросы. `budget.py` хранит месячный лимит и резервы. `telegram.py` сохраняет Updates без polling. `worker.py` доставляет PostgreSQL jobs. `api.py` задаёт владельца из серверной конфигурации и требует Bearer credential. Любые новые фоновые процессы используют те же таблицы и проверяют права.

## Validation and Acceptance

«Резюме не обновил» и «Резюме обновил?» оставляют исходную задачу активной и reminder сохранённым. После «Завтра напомни обновить резюме» ответ «в 19:00» создаёт ровно одну задачу и reminder на сохранённую дату. Именованная старая задача находится среди более ста записей; две одинаково подходящие задачи требуют уточнения. После падения до/после разбора новый процесс подбирает источник без replay. Edit reminder требует подтверждения и меняет reminder, сохраняя план и дедлайн. Известный неоплаченный отказ допускает корректный повтор, timeout остаётся заблокированным.

## Idempotence and Recovery

Все синтетические данные находятся в отдельной локальной PostgreSQL. Технические повторы не создают второй результат. Не удалять незнакомые базы или volumes; миграционные откаты допустимы только в тестовой базе. Перед остановкой записать реальные результаты и дальнейший шаг сюда и в матрицу приёмки.
