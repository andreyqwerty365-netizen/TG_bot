## Purpose / Big Picture

Владелец должен иметь возможность безопасно сохранять дела, уточнять время коротким ответом, находить старые задачи и возвращаться к сохранённому сообщению после сбоя. Сначала доказать исправление шести критических проблем на отдельной PostgreSQL. Затем добавлять работающий React-интерфейс к тому же backend, почтовую синхронизацию только после настройки, сопровождение и процедуры восстановления.

## Surprises & Discoveries

Почтовые регрессии сначала воспроизвели устаревшее предложение при разборе старой версии после новой, starvation папки Sent при большом INBOX, невозможность восстановить старый pointer после UIDVALIDITY, допустимый серверный UID после MIME literal, очистку ещё не разобранного источника и скрытие старого review после ста нерелевантных писем. Исправления подтверждены отдельными красными/зелёными тестами. Курсор не должен считать checkpoint proof of analysis: он доказывает только commit источника, который потом подбирает source worker. Synthetic transport не доказывает совместимость с живым IMAP.

Предыдущий аудит описывает 124 успешных теста, но не содержит тестов перечисленных пользователем отрицаний и короткого ответа времени. `language.py` стирает вопросительные знаки до распознавания завершения. `context.py` читает только 65 последних задач и запрещает поиск по названию при более восьми кандидатах. Редактирование источника всегда превращается в изменение заголовка. `BudgetLedger.reserve` блокирует даже статус failed с нулевым списанием. Worker восстанавливает доставку, но не подбирает необработанные источники без повторного Telegram Update.

На Windows отсутствовали полноценный Git и PostgreSQL. Официальный переносимый Git находится вне репозитория в `../.tools/mingit`; PostgreSQL для тестов также загружается вне репозитория. Graphify не запустился: установленный Python launcher недоступен, попытка использовать его пакеты из Python 3.12 обнаружила несовместимый бинарный tree_sitter. Исходники анализируются напрямую; граф не объявляется построенным.

Сверка дерева после публикации обнаружила ошибку вспомогательного сборщика payload: промежуточный коммит `01418d3` содержал только Docker ignore. Сборщик исправлен вне репозитория; полный код опубликован следующим `557f2d2`, без force push. Совпадение полного дерева подтверждено через fetch и пустой `git diff --cached origin/codex/personal-crm-reliability-web`. Нельзя считать наличие remote commit доказательством полноты без такой сверки.

## Decision Log

Почтовый этап использует сменный протокол и первый IMAP SSL адаптер с EXAMINE/BODY.PEEK, явными папками INBOX/Sent и серверными секретами. Два независимых разрешения enabled/consent по умолчанию false проверяются до создания сетевого клиента. Реальный ящик в этой сессии не подключать. Синхронизация сохраняет источник, metadata и checkpoint одной PostgreSQL транзакцией, разбор выполняет существующий независимый source worker. Без облачного ИИ консервативные локальные правила распознают просьбы, собственные обещания, явные даты ISO и изменения единственной связанной задачи; неопределённые случаи показываются как требующие ручного просмотра. Классификация не считается оценкой качества реального ИИ.

Опасное завершение блокировать детерминированно до обращения к модели. Подтверждения проверять по владельцу, аккаунту и версии. Ограниченный контекст модели не использовать как доказательство уникальности задачи: однозначные ссылки и поиск должны проверяться запросом ко всей PostgreSQL.

Для краткого ответа времени сохранять уже разрешённую календарную дату в pending_action, чтобы перезапуск или смена дня не переинтерпретировали «завтра». Потенциально оплаченные запросы не повторять автоматически. Статус достоверно неоплаченного отказа допускает новый резерв, только после проверки бюджета; повтор источника Telegram не запускает бесконечный цикл.

## Outcomes & Retrospective

Третий законченный результат — локальная почтовая интеграция без доступа к ящику. Полный PostgreSQL набор вырос со 165 до 197, UI unit с 3 до 6, browser с 8 до 10. Стенд на 127.0.0.1:8001 использует только `mail_demo:create_demo_app` с `personal_crm_test_web` и синтетическим владельцем; отдельный source worker обрабатывает сохранённые источники. IMAP, Telegram и платный ИИ не подключались. Консервативная локальная грамматика не заявляется универсальным пониманием писем; сложные письма доступны для ручного просмотра. Следующие незавершённые объёмы — D/E, а живой mail pilot требует отдельного выбора провайдера/прав/согласия.

Первый законченный результат: исправлены перечисленные критические ошибки и включён самостоятельный source worker. 145 CRM тестов прошли на настоящей PostgreSQL, включая 21 новый сценарий. Первый прогон до исправлений воспроизвёл ложное закрытие, потерю краткого уточнения, невозможность поиска старого дела, неправильное поле edit и блокировку неоплаченного retry. Дополнительно исправлены поиск вопросов за пределами восьми и одновременная правка title/reminder. Полный прогон выполняет down/up/check и сохранение записей при аддитивном upgrade. Три демонстрации прошли без внешних вызовов. Docker отсутствует; Compose не объявляется проверенным.

Второй законченный результат: полноценное локальное приложение React/TypeScript. Все пять разделов работают с существующей PostgreSQL, никакие задачи не сохраняются отдельно в браузере. Поиск Unicode не зависит от локали PostgreSQL, фильтры сроков учитывают сохранённый пояс и точность, формы различают срок/план/напоминание. Пользователь может приостановить ИИ и снизить бюджет в пределах разрешённого серверного потолка; эти проверки стоят под PostgreSQL lock до SDK. Дополнительные два сценария сохранили первоисточник после уточнения и запретили два конкурентных создания. Итог: 165 passed, 39.04s; legacy 133 passed, 7.96s; unit 3 passed; browser E2E 8 passed, 7.9s. Проверены privacy filter, CSP/frame/nosniff. Production, Docker и внешние аккаунты не проверялись.

## Context and Orientation

`src/personal_crm/service.py` сохраняет SourceVersion до интерпретации, затем применяет изменения и историю под блокировкой профиля. `language.py` распознаёт ограниченные команды. `context.py` строит кандидатов и постоянные вопросы. `budget.py` хранит месячный лимит и резервы. `telegram.py` сохраняет Updates без polling. `worker.py` доставляет PostgreSQL jobs. `api.py` задаёт владельца из серверной конфигурации и требует Bearer credential. Любые новые фоновые процессы используют те же таблицы и проверяют права.

`workspace_api.py` предоставляет owner-scoped `/workspace/tasks`, `/workspace/projects`, `/workspace/inbox`, `/workspace/settings` и ответы на источник. Ручное создание сохраняет idempotent source и задачу одной транзакцией; формы редактирования используют версии и общую транзакцию с history/jobs. Новые Project и nullable Task.project_id не меняют существующие записи. `Task.title_search` заполняется Python casefold при insert/update и миграцией для старых данных, поэтому поиск работает с русским регистром и локалью C. `web/src/App.tsx`, `screens.tsx`, `components.tsx`, `api.ts` реализуют интерфейс; `web/e2e/workspace.spec.ts` обращается к живому серверу. `web/README.md` содержит точные команды и отдельную синтетическую E2E БД.

## Validation and Acceptance

«Резюме не обновил» и «Резюме обновил?» оставляют исходную задачу активной и reminder сохранённым. После «Завтра напомни обновить резюме» ответ «в 19:00» создаёт ровно одну задачу и reminder на сохранённую дату. Именованная старая задача находится среди более ста записей; две одинаково подходящие задачи требуют уточнения. После падения до/после разбора новый процесс подбирает источник без replay. Edit reminder требует подтверждения и меняет reminder, сохраняя план и дедлайн. Известный неоплаченный отказ допускает корректный повтор, timeout остаётся заблокированным.

## Idempotence and Recovery

Все синтетические данные находятся в отдельной локальной PostgreSQL. Технические повторы не создают второй результат. Не удалять незнакомые базы или volumes; миграционные откаты допустимы только в тестовой базе. Перед остановкой записать реальные результаты и дальнейший шаг сюда и в матрицу приёмки.
